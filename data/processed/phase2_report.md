# Phase 2 Prototype Report

작성일: 2026-06-06

## 결론

현재 공개자료만으로는 PRD의 표준 Backtesting 지표(Precision, Recall, F1, AUC-ROC)를 투표소 단위로 유효하게 계산할 수 없다.

이유:
- 선관위 투표현황 API는 송파구 단위 1행 집계만 제공한다.
- 선관위 투표소 API는 투표소명과 주소를 제공하지만 투표소별 선거인수는 제공하지 않는다.
- `shortage_2026.csv`는 공식 집계 67행을 보존하지만, 송파구 실제 부족 14곳 중 언론/공개자료로 투표소명이 확인된 행은 8곳뿐이다.

따라서 Phase 2는 "완전한 성능평가"가 아니라 "송파구 샘플 기반 가능성 점검"으로 수행했다.

## 생성 산출물

- `songpa_2022_precincts.csv`: 선관위 투표현황 API 결과. 송파구 전체 1행 집계.
- `songpa_2022_polling_places.csv`: 2022 송파구 선거일 투표소 143개.
- `songpa_2026_polling_places.csv`: 2026 송파구 선거일 투표소 146개.
- `songpa_shortage_matches.csv`: 2026 투표소 목록과 매칭된 송파구 부족 투표소 8개.
- `songpa_phase2_risk_prototype.csv`: 146개 송파구 투표소 위험도 프로토타입.
- `phase2_metrics.json`: 계산 가능한 범위와 계산 불가 지표 사유.

## 방법

1. `shortage_2026.csv`의 송파구 투표소명 확인 행을 정규화했다.
2. 2026 송파구 투표소 API 목록과 매칭했다.
3. 2022 개표결과 엑셀의 `구·시·군의장` 시트에서 송파구 읍면동별 `소계`와 `선거일투표` 행을 추출했다.
4. 투표소별 선거인수가 없으므로 2022 읍면동 선거인수와 선거일투표수를 2022년 같은 읍면동 투표소 수로 균등 배분했다.
5. M1은 PRD의 50% 기준선 모델을 적용했다.
6. M2는 정식 회귀가 아니라 2022 선거일투표수 균등배분 proxy를 사용했다.
7. M3 위험도는 `예상_본투표수 / 배부량_추정`으로 계산했고, 확인된 부족 투표소는 RED 사실값으로 라벨링했다.

## 지표

- 송파구 공식 실제 부족 투표소: 14개
- 공개자료로 이름 확인된 송파구 부족 투표소: 8개
- 2026 투표소 API 매칭: 8개
- 이름 라벨 커버리지: 57.14%
- positive-only recall@14: 12.5%
- positive-only recall@20: 25.0%

표준 Precision/Recall/F1/AUC-ROC는 `null`로 둔다. 완전한 음성 라벨과 투표소별 선거인수 없이 계산하면 검증 안 된 수치를 사실처럼 제시하는 문제가 생긴다.

## 다음 조건이 충족되면 정식 Phase 2 가능

- 선관위 또는 진상규명위가 67개 추가 송부 투표소의 개별 명단을 공개한다.
- 50개 실제 부족, 22개 투표 중단, 17개 미사용을 투표소 단위로 식별할 수 있다.
- 투표소별 선거인수 또는 투표구-투표소 매핑 자료를 확보한다.
